# 华为云 CodeArts 研发交付物规范

> 本文件供 Phase 3 生成可直接录入 CodeArts 的工作项、分支、MR 等研发交付物。Skill 不调用 CodeArts API，只生成结构化内容供人录入。

## CodeArts Req 工作项

### 工作项类型

| 类型 | 用途 | 对应 |
|------|------|------|
| Epic | 大特性 | 跨迭代 |
| Feature | 特性 | 单迭代可完成 |
| Story | 用户故事 | Phase 1 的 Story |
| Task | 任务 | Phase 2 的子任务 |
| Bug | 缺陷 | 流水线/测试发现 |

### Story 条目字段

```
标题: <Story 标题>
工作项类型: Story
优先级: <P0/P1/P2/P3>
迭代: <Sprint-N>
故事点: <估算>
描述:
  ## 背景
  <为什么做>
  ## 验收标准
  - [ ] AC1
  - [ ] AC2
  ## 技术说明
  <接口/数据模型/依赖>
关联: <Epic/Feature>
```

### Task 条目字段

```
标题: <子任务标题>
工作项类型: Task
所属 Story: <关联 Story>
预估工时: <人日>
技能域: <前端/后端/测试>
描述:
  ## 任务内容
  <具体做什么>
  ## 完成标准
  - [ ] ...
```

## 分支命名规范

```
<类型>/<迭代号>-<Story号>-<简述>
```

| 类型 | 场景 | 示例 |
|------|------|------|
| feature | 新功能 | feature/s26-101-user-list-pagination |
| bugfix | 缺陷修复 | bugfix/s26-103-login-redirect |
| hotfix | 紧急修复 | hotfix/104-payment-timeout |
| refactor | 重构 | refactor/s26-105-order-service |

规则：
- 全小写，单词用连字符
- 简述 ≤ 4 个单词
- 从 develop 拉分支，合并回 develop

## 提交规范（Conventional Commits）

```
<type>(<scope>): <subject>

<body>

<footer>
```

| type | 含义 |
|------|------|
| feat | 新功能 |
| fix | 缺陷修复 |
| refactor | 重构 |
| test | 测试 |
| docs | 文档 |
| chore | 构建/工具 |

示例：`feat(user): 支持列表分页 S-101`

## MR（合并请求）描述模板

```
## 变更说明
<本次 MR 做了什么，为什么>

## 关联工作项
- Story: S-101
- Task: T-201, T-202

## 变更内容
- <主要改动点1>
- <主要改动点2>

## 自测清单
- [ ] 本地启动通过
- [ ] 新增单元测试通过
- [ ] 验收标准逐条验证
- [ ] 无 console/调试代码残留
- [ ] 接口契约未破坏（或已同步通知）

## 验收标准映射
- [x] AC1: 列表支持分页 → 已实现
- [x] AC2: 默认每页 20 条 → 已实现

## 风险/注意
<对 Reviewer 的提示>

## 部署影响
- [ ] 需要数据库迁移
- [ ] 需要配置变更
- [ ] 无
```

## 自测清单（通用）

开发完成前逐项确认：
- [ ] 代码通过本地编译/启动
- [ ] 新增逻辑有单元测试
- [ ] 命名/注释符合团队规范
- [ ] 无硬编码配置/密钥
- [ ] 异常分支已处理
- [ ] 日志可观测
- [ ] 验收标准全部满足

## 技术风险识别规则

从 Story 描述/技术说明中识别技术风险点，输出风险项 + 建议动作，供开发前预判（Skill 给建议，由人确认执行）。

**风险识别规则表**：

| 风险信号（描述中出现） | 风险类型 | 建议动作 |
|------------------------|----------|----------|
| 旧表/历史数据迁移/数据结构变更 | 数据风险 | 需 DBA 评审 + 制定回滚预案 + 灰度执行 |
| 第三方 API/外部服务依赖 | 集成风险 | 契约测试 + 降级/熔断策略 + 超时配置 |
| 大数据量/10万行/批量/性能要求 | 性能风险 | 先做性能 POC + 设容量上限 + 监控埋点 |
| 权限/鉴权/敏感数据/用户隐私 | 安全风险 | 安全评审 + 最小权限原则 + 审计日志 |
| 并发/分布式/锁/事务 | 并发风险 | 并发用例 + 边界测试 + 死锁排查预案 |
| 重构/大范围改动/核心模块 | 回归风险 | 影响面分析 + 回归测试集 + 灰度发布 |
| 未知/待确认/TBD | 不确定性 | 标注需澄清，不强行实现 |

**输出格式**：

```
| # | 风险项 | 类型 | 信号来源 | 建议动作 | 优先处理 |
|---|--------|------|----------|----------|----------|
| 1 | {{风险}} | {{类型}} | {{描述片段}} | {{动作}} | 是/否 |
```

无识别到风险时输出"未识别到高风险信号，按常规流程推进"。

## AC → 测试用例骨架

每条验收标准映射为测试场景矩阵（正常/边界/异常），生成测试用例骨架供开发前补全，替代人脑逐条设计测试场景的重复劳动。

**映射规则**：
- 每条 AC 生成 3 类测试场景：正常路径（满足条件）、边界路径（临界值/空值/极值）、异常路径（违反条件/错误输入）
- AC 含数值条件 → 边界取 临界值±1、0、最大值
- AC 含权限/角色 → 异常取 无权限/越权角色
- AC 含"支持/可选" → 边界取 未配置/默认配置

**输出格式**：

```
| AC | 测试场景 | 输入 | 期望结果 |
|----|----------|------|----------|
| AC1: {{标准}} | 正常 | {{输入}} | {{期望}} |
| AC1 | 边界 | {{临界输入}} | {{期望}} |
| AC1 | 异常 | {{非法输入}} | {{期望}} |
```

此为骨架，具体测试数据由开发/测试人员补全；Skill 不生成真实测试数据。

## 动态自测清单裁剪规则

通用自测清单（7项）按 Story 类型动态裁剪，避免重构类需求被要求"验收标准映射"等无关项。

**Story 类型识别**（从标题/描述/分支类型推断）：
- 新功能（feature）→ 全量清单
- 重构（refactor）→ 去掉"验收标准逐条验证"，增加"行为等价证明（重构前后输出一致）"
- 缺陷修复（bugfix）→ 增加"复现原缺陷的用例已通过"、"回归关联功能"
- 性能优化 → 增加"性能指标对比（优化前后）"、"压测结果达标"
- 文档（docs）→ 仅保留"命名/注释规范"、"无调试残留"

**输出格式**：

```
本次 Story 类型：{{类型}}，自测清单（裁剪后）：
- [ ] {{适用项1}}
- [ ] {{适用项2}}
...
> 已裁剪项：{{被去掉的项及原因}}
```

## Code Review 流程提示

生成 MR 时同步给出 Code Review 建议，替代人脑判断"找谁看、看什么"。

**Reviewer 建议规则**：

| 变更涉及技能域 | 建议 Reviewer |
|----------------|---------------|
| 后端接口/数据 | 后端资深 + 该域 Owner |
| 前端组件/交互 | 前端资深 + 设计系统 Owner |
| AI/模型/Prompt | AI 方向工程师 + 业务域 Owner |
| 跨域/公共组件 | 技术负责人 + 各域代表 |
| 安全/权限相关 | 安全 Owner 必审 |

**Review 重点按变更类型**：

| 变更类型 | Review 重点 |
|----------|-------------|
| 新功能 | AC 覆盖完整性 + 接口契约 + 边界处理 |
| 重构 | 行为等价 + 影响面 + 无新增副作用 |
| 缺陷修复 | 根因是否真正消除 + 是否引入新缺陷 |
| 性能优化 | 指标对比公平性 + 是否牺牲可读性/正确性 |

**Review 检查清单**：
- [ ] 变更与 MR 描述一致
- [ ] 自测清单已全部勾选
- [ ] 风险项已有应对
- [ ] 命名/注释/规范一致
- [ ] 无调试代码残留
- [ ] 无硬编码配置/密钥

**输出格式**：

```
建议 Reviewer：{{人/角色}}（依据：{{技能域匹配}}）
Review 重点：{{按变更类型}}
Review 检查清单：（上述清单）
```
